# AI 自动化开发流程

本文用于约束 AI 在 `ai` 的业务需求中按统一流程完成需求理解、方案拆解、工程实现、验收验证和交付说明。本文只写流程和模板，不写私有接口地址、默认账号、私有 IP、真实 token 或本机绝对路径；`ai` 的具体边界以根目录 `AGENTS.md` 为准。

## 完整功能与交付证据

修改按 `AGENTS.md` / `BRANCHING_SPEC.md` 核对基线、WIP 和授权，完整记录实现、测试、文档、migration、公共契约及必需跨仓配套。main/test/preprod 分别记录实际集成的固定 HEAD，不把中间分支验证或一次 push 当作 main、制品、部署的验收。

正式 main 交付并完成远端包含核对后，按已有授权清理本任务本地/远程短分支；未合或其他 worktree 在用的分支保留。推送 main 后核对精确提交的 CI（本仓库需手动触发，见 `AI_ENGINEERING_GUARDRAILS.md` Definition of Done）。交付说明须包含验证命令与结果、CI 结论、未覆盖风险、发布状态、分支/worktree 保留或清理原因。Review 是补充检查，不替代独立风险验证，也不增设人工批准门禁。

## 一、标准流程

1. AI 需求说明：先明确业务背景、调用方、功能包归属、接口入口、鉴权方式、数据库、租户、敏感字段、模型调用链路和不做范围。
2. AI 验收标准：在开发前列出接口、数据库、权限、安全、AI 专项、测试、回归和发布验收点。
3. AI 开发手册：写清 Controller、请求/响应 `record`、Service、Repository、Entity、PostgreSQL 脚本、鉴权路径、配置和测试入口。
4. AI 工程实现：先数据模型，再 Repository，再 Service，再 Controller，最后补 SQL、鉴权和测试；每一步都遵守功能分包和注释规范。
5. AI 测试说明：说明执行过的编译、测试、密钥扫描、请求层测试、SQL 验证、鉴权验证和联调验证；涉及网络、并发、超时、SSE 的测试写明连续三轮结果。
6. AI 提交说明：说明改动范围、影响接口、影响表、鉴权、配置项、兼容影响、回滚方式和未覆盖风险。
7. 回归发布说明：说明 SQL 执行顺序、配置刷新、服务重启、数据修复、CI 结论和回滚策略。

## 三、验收标准模板

```markdown
# AI 验收标准 - <需求名称>

## 接口
- [ ] 新增接口参数校验正确。
- [ ] 修改接口只更新允许字段，并携带期望 version。
- [ ] 删除接口符合软删或硬删要求。
- [ ] 新增管理类资源接口符合 RESTful；对话 SSE 符合 typed SSE 合同。

## 数据库
- [ ] 表字段、索引、默认值、唯一约束正确，公共治理字段齐全。
- [ ] 租户方式正确：用户/租户数据显式写 tenant_id，平台数据用 @InterceptorIgnore 并限定平台范围。
- [ ] 逻辑删除和乐观锁 version 处理正确。
- [ ] 增量脚本可重复执行，已追加到 PostgresqlDdl#getSqlFiles()，并同步 H2 schema.sql。
- [ ] 全新或空业务库首次启动前，已先执行 utils 的 db/postgresql/common-infra-schema.sql，再执行 db/postgresql/ai-schema.sql。

## 权限
- [ ] 受保护接口经过 AiRequestIdentityResolver 或 AiControlPlaneAdministrator。
- [ ] 平台控制面要求活跃的 PLATFORM_SUPER_ADMIN 且具备 user:auth:manage。
- [ ] 涉及 admin-web 页面时，前端入口与权限资源已同步。

## 安全
- [ ] 未登录、无权限和跨租户访问被拒绝。
- [ ] 替换他人 id、会话 ID 或 tenantId 无法越权。
- [ ] SQL 注入、XSS、文件遍历、SSRF、批量赋值和资源消耗风险已检查。
- [ ] 日志、异常响应和测试数据不含密钥、token、用户隐私和内部服务地址。

## 敏感信息
- [ ] 手机号、邮箱、身份证、地址、联系人、token、apiKey、签名 URL、患者资料等敏感字段已识别。
- [ ] 普通列表、详情、日志、异常只返回或记录脱敏值。
- [ ] 明文查看使用独立接口，并要求登录、专门权限、租户校验和审计。

## AI 专项
- [ ] Agent 经 Nacos AI Registry 调用；AgentCard 或接口地址缺失时显式失败。
- [ ] Prompt 来自 ai_role_prompt，保留“不能替代医生诊断、治疗、用药或急救判断”的安全边界。
- [ ] 多模态附件校验协议、数量、远程 Content-Type 和 MIME。
- [ ] 对话记忆保留条数上限、时间窗口和用户归属校验。
- [ ] 审计的成功、失败、取消都显式写入 tenant_id。
- [ ] 模型执行仍在 ai-agent；ai 只经 AiModelSelectionService 维护默认 Provider，不直接绑定模型供应商。
- [ ] 跨服务改动已同步核对 ai-agent 中同一轮请求使用同一个 CurrentClient。

## 测试
- [ ] Controller 请求层测试覆盖成功路径，以及未登录、无权限、跨租户和参数错误。
- [ ] Service 测试覆盖核心业务分支。
- [ ] Repository 或 SQL 验证覆盖关键查询条件。
- [ ] 测试符合 TESTING_SPEC.md「测试稳定性」；涉及网络、并发、超时、SSE 的测试连续三轮通过。
- [ ] 没有用重试、跳过、放宽断言或删除测试换取通过。

## 回归
- [ ] 不影响同模块已有接口。
- [ ] 不影响登录、鉴权、租户、统一响应和异常处理。
- [ ] README、AI 规范和接口文档已同步。
- [ ] 推送 main 后，精确提交的 CI 已手动触发、headSha 一致且通过。
```

## 五、多智能体流程

- 主智能体负责最终需求边界、功能包归属、实现方案、代码合并、测试结论、提交说明和发布风险判断。
- 子智能体默认只做需求分析、项目学习、问题排查、代码 Review、测试回归和日志分析。
- 子智能体不得自行提交、推送、切分支、修改未分配文件、写死测试租户、写死测试用户、写入私有 IP、写入 token、写入 apiKey 或写入本机绝对路径。
- 多个 worker 只有在写入边界清楚时才能并行，例如一个只改后端接口，一个只改前端页面，一个只补测试。
- 如果多个 worker 可能修改同一个核心 Service、Repository、SQL 脚本、鉴权、租户、Prompt、对话记忆、审计或统一异常，必须由主智能体串行处理。

## 六、子智能体输出要求

- 结论：说明功能包归属、接口链路、配置状态或异常原因。
- 证据：提供类名、方法名、SQL、表名、配置文件、日志关键字或行号。
- 风险：说明是否影响鉴权、租户隔离、敏感字段、患者资料、模型调用链路、公共工具、启动配置或部署脚本。
- 建议：只提出建议，不替主智能体做最终决策。
