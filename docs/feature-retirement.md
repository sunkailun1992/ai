# 功能退役与数据边界

个人项目已退役对话式问卷：HTTP 路由、状态机、模板种子、答案解释与自然追问、完成 outbox、问卷派生记忆写入以及对应 Agent 能力均已移除。普通患者分析、可信身份、租户隔离、文件安全、会话记忆和审计继续独立维护。

个人小程序客户端已退出开发目录。从 AI 1.6.9 起，服务端微信登录/用户/opaque 会话、owner 专属会话元数据/展示消息、旧上传登记/元数据/token 刷新管理路由与对应实体/Repository/Service/DTO 均移除，不保留 NoOp 或兼容入口。普通 User 聊天、命名空间记忆、审计、RAG、附件 URL 校验、既有文件 token view GET/HEAD 和 DB 存储控制面继续维护；未新增 User 直传或文件 owner 管理 API。

数据清理仅针对个人 PostgreSQL 中退役功能的专属记录及精确关联记录。执行前必须确认旧服务已停止、把目标行备份到 Git 外的受限目录，再在事务内清理并逐项读回；普通 AI 文本记忆、审计和 RAG 来源不得混入清理条件。私有备份、凭据及原文不进入本仓库。

已发布的历史数据库初始化和迁移脚本保留为历史记录，不借退役重写既有 MySQL 历史。当前代码不再注册退役实体、导入模板或调用旧接口；不得从历史脚本重新启用退役业务。当前 PostgreSQL 结构基线仍含退役表定义且由 DDL runner 引用，全新库可能仍建出空旧表；这是独立引导/迁移清理边界，不等同功能仍启用。现有表结构是否物理删除属于单独数据库迁移，数据清理不以自动 DROP 代替。

验证同时覆盖编译与完整业务回归、Agent 退役端点 HTTP 404、Jar 中无退役类和模板，以及目标数据清理后的独立读回。源码、数据清理、实际制品、部署和浏览器验收分别报告。
